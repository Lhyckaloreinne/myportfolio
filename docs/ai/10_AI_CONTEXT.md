# AI Context

## Purpose

This document serves as the primary onboarding guide for AI coding assistants working on the Personal Career Platform.

Its purpose is to provide project context, design philosophy, engineering standards, and development expectations so that AI-generated outputs remain consistent throughout the project.

AI should prioritize maintaining the project's architecture, design language, and coding standards rather than generating isolated solutions.

---

# Project Overview

The Personal Career Platform is a modern, minimalist, and professional portfolio website built to showcase multiple professional specializations within a single cohesive personal brand.

The platform is designed to present work across:

- UI/UX Design & Front-End Development
- Data Analytics
- Graphic Design
- Executive Support & Digital Operations

Rather than appearing as multiple unrelated portfolios, the platform should present one unified professional identity while allowing recruiters to easily explore the specialization most relevant to them.

The portfolio should demonstrate not only completed work but also organization, design thinking, problem-solving, and software engineering practices.

---

# Project Goals

The project should:

- Showcase professional work.
- Demonstrate software engineering practices.
- Follow modern UI/UX principles.
- Be fully responsive.

- Reflect real-world software development workflows.

# Development Principles

AI should prioritize:

- Clean architecture
- Readable code
- Reusable components
- Accessibility
- Responsive layouts
- Performance
- Maintainability
- Scalability

Avoid unnecessary complexity.

Prefer simple solutions when they satisfy project requirements.

---

# Coding Standards

When generating code:

- Use TypeScript.
- Follow Next.js App Router conventions.
- Prefer Server Components unless interactivity requires Client Components.
- Use Tailwind CSS utilities.
- Avoid inline styles.
- Build reusable components.
- Keep components focused on a single responsibility.
- Use semantic HTML whenever possible.
- Maintain accessibility best practices.

---

# Component Philosophy

Every reusable UI element should become its own component when appropriate.

Examples include:

- Navigation Bar
- Footer
- Hero Section
- Section Header
- Feature Card
- Project Card
- Skill Card
- Timeline
- Badge
- Button

Avoid duplicating UI implementations.

---

# Design Expectations

The interface should prioritize:

- Excellent typography
- Consistent spacing
- Large whitespace
- Editorial layouts
- Soft shadows
- Rounded corners
- Subtle animations
- Premium visual quality

Animations should support usability rather than attract unnecessary attention.

---

# Content Guidelines

Content should remain:

- Professional
- Clear
- Concise
- Authentic
- Recruiter-focused

Avoid excessive marketing language or exaggerated claims.

The portfolio should communicate competence through quality of work rather than overly promotional copy.

---

# AI Collaboration Guidelines

When assisting with development:

- Explain the reasoning behind technical decisions.
- Recommend industry best practices.
- Preserve the existing project architecture.
- Avoid unnecessary dependencies.
- Avoid overengineering.
- Prefer maintainable solutions over clever solutions.
- Keep documentation synchronized with implementation when changes affect architecture or development decisions.

If multiple approaches are available, explain the trade-offs before recommending one.

---

# Long-Term Vision

This project is more than a portfolio.

It serves as:

- A personal brand platform.
- A learning project for modern software engineering.
- A demonstration of front-end development skills.
- A showcase of design thinking.
- A living project that will continue to evolve throughout the developer's career.

All future improvements should support these long-term objectives while preserving simplicity, consistency, and maintainability.
