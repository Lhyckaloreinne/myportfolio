# Portfolio Content Guide

> **Purpose**
>
> This document defines how the portfolio website organizes, presents, and generates content.
>
> It serves as the bridge between the project documentation and the final portfolio implementation.
>
> While project metadata provides factual information and templates define presentation, this guide explains how every section of the portfolio should use those resources.
>
> This document is intended for both manual development and AI-assisted generation.

---

# Portfolio Goal

The portfolio aims to present my work through thoughtful storytelling rather than simply displaying finished designs.

Each section should demonstrate:

- My problem-solving approach
- My design thinking process
- My technical capabilities
- My professional growth

The portfolio should feel cohesive, intentional, and easy to explore.

# Case Study Generation

Every UI/UX case study follows the same generation workflow.

```text
Project Metadata

↓

Extract Project Facts

↓

Apply UI/UX Case Study Template

↓

Generate Case Study

↓

Render Portfolio Page
```

The metadata remains the single source of truth.

The template defines presentation.

---

# Image Usage

Images should reinforce the project narrative.

Guidelines:

- Use a dedicated cover image for each project.
- Group screenshots logically.
- Prioritize high-quality visuals.
- Avoid unnecessary repetition.
- Maintain a consistent folder structure.

Images support the story—they should never replace it.

---

# AI Content Workflow

When generating UI/UX content:

```text
Read Metadata

↓

Extract Facts

↓

Apply Case Study Template

↓

Generate Narrative

↓

Insert Images

↓

Produce Final Portfolio Page
```

AI should never generate content that is not supported by the metadata.

---

# Writing Principles

All generated content should:

- Be factual
- Be concise
- Explain design reasoning
- Maintain a professional tone
- Focus on problem-solving
- Avoid exaggerated claims

# Portfolio Philosophy

The portfolio is more than a collection of projects.

It is a reflection of how I approach problems, develop solutions, and continuously grow as a designer and developer.

Every project should communicate:

- The context
- The challenge
- The thought process
- The solution
- The outcome
- The lessons learned

The goal is not to showcase every screen.

The goal is to tell meaningful stories supported by thoughtful design decisions.
